# Blender 积木人物与场景动画

## 何时使用

积木人物、完整积木场景、生产线与机械动作默认采用这条本地三维路径。使用真实几何、材质、灯光和关键帧；网页图形工具继续用于截图、图示和文字。用户明确选择云端生成时再切换；平台的少量试用额度不能当作已验证的免费生产方案。

当前任务是在更新技能或只做独立动画时，不索要口播 SRT。实际为当前口播剪辑时，仍先确认对应 SRT，才查看工程并排入相应区间。独立样片可以直接采用用户描述的动作和合理时长；完成素材不代表已经导入或放入剪映时间线。

## 已跑通的基线与模板

2026-10-23 已用 Blender 4.5.15 LTS、macOS Apple Silicon 完成 9 秒积木工厂动画：1280×720、24fps、216 帧、Eevee Next 32 samples，PNG 序列转 H.264 MP4，并配本地合成机械声。这个记录证明该流程实际产出过视频，不代表所有电脑的渲染速度、所有动作或更高质量已验证。

可复用源码：[积木工厂](../assets/blender/brick_factory.py)、[示例机械声](../assets/blender/mechanical_foley.py)。它们是固定 9 秒、24fps 案例的起点，不是任意口播自动转三维的引擎。先复制到本次任务 `work/`，再按语义、时长和设计改动；不在技能库里写业务项目。源码不使用外部角色模型、付费插件或云端生成。

## 制作步骤

1. **先确定可见因果。** 写清主体、动作、触发点和结果。示例为“走近控制台 → 手接触并压下按钮 → 指示灯点亮 → 传送带与产品启动 → 压头装配 → 成品输出”。所有对象共用一个时间基准，避免手未接触就启动、产品静止而传送带在转。口播任务按 SRT 实际区间换算，独立案例使用秒和帧。
2. **建立完整积木世界。** 地台、墙板、传送带、机器、控制台、产品都有可辨识的积木结构与凸点。按镜头需要添加滚轴、支撑、栏杆、连接线和面板，明确物件之间的空间关系。优先复用已有组件与人物；已有可用的 `.blend` 或授权资产时先读其结构，再修改。场景简化应保留轮廓、尺度和动作逻辑。
3. **人物采用分层刚性结构。** 示例由圆柱头、梯形躯干、独立腿部枢轴、分段手臂、C 形手、服装细节和头盔组成；眼睛和笑脸独立建模。把肢体、脸部与服饰挂在人物/头部父节点下，保持统一比例和外观。走路、抬手、按压、收手和转头分别设置关键帧；肢体按刚性零件运动，不用整体拉伸模拟表演。
4. **材质与灯光共同塑造塑料质感。** 使用 Principled BSDF、合理粗糙度、轻度 Coat、倒角与合适法线，给硬边可读的高光。示例 roughness 约 0.28、Coat Weight 约 0.28，倒角 2–4 段，仅作起点。搭配大面积暖主光、冷轮廓光和柔和前补光，设置地面与接触阴影，并用 AgX 控制高光。配色、服装与灯光按本片选择，不把案例的青橙色强制套到所有视频。
5. **按同一时间驱动物件。** 用确定性函数计算关键姿态后烘焙到关键帧，使 `.blend` 脱离生成脚本仍能播放。按钮有真实位移与回弹；传送带条纹循环移动；产品沿轨道移动并经历可见加工状态；压头与指示灯按触发先后动作。父节点变换后，接触点需在同一坐标系中计算，检查手、按钮、产品和压头的实际位置。
6. **镜头覆盖关键动作。** 示例采用场景全景、按键近景、装配局部、运转全景，并在镜头内做克制推进；按叙事调整镜头数量和时长。用相机时间标记完成切换，保持主要空间轴线。按键近景同时读得清手与按钮，并给头顶留余量；结果镜头需要有足够停留，不能只展示没有动作的漂亮模型。
7. **保存工程并逐帧渲染。** 新项目隔离运行，保留源码、`.blend` 与 PNG 序列；正式分辨率和帧率服从当前任务。长任务保留实际进度，报错后定位具体帧和状态，需要时从未完成范围恢复。完整画面动画交付 MP4；需要透明叠加时走下述独立 Alpha 配置，不能把不透明 MP4 当作透明包装。
8. **声音与交付。** 按按钮接触、回弹、传动启动和加工峰值放声音。示例声音为原创程序合成的机械示意，不冒称真实 Foley 或剪映同名音效；音效不是每次都必须照搬。独立样片交付实际视频，可附可编辑 `.blend`；整片口播仍由既有全片同步、画中画与一次批量导入流程承接。

## 本次制作中修正过的问题

- 近景把头盔切出画面：提高相机观察点并适当放宽镜头，保留头部与按键动作。
- 零件尚未装配却悬浮成一张薄片：只缩 Z 会留下可见的 XY 平面；按本例同时缩放 XYZ，或用符合镜头的显隐控制，正确安排出场。
- 压头与成品相交：按产品最高点和压头底面重算行程，给装配状态留间隙，不用增加发光或切镜掩盖穿模。
- 中止后重启渲染共用日志：新一次运行使用独立日志，确认旧进程结束再启动，避免两个进程同时写日志和输出帧。

这些是本次发生过的具体问题。制作过程中按构图和动作需要查看必要帧即可，不扩展成每次必做的测试片、逐张审批或整片验收。

## 运行方式

先定位已安装 Blender 的实际可执行文件，优先复用现有环境。个人安装可查询可选的 `.local/runtime.json`；它只保存机器路径，不随公开仓库发布。缺失时说明需要的工具，并在已授权范围内从官方站点获取匹配架构的发行包；不自动改用云端或低维动画充数。

在任务目录中复制模板后运行（将 `blender` 替换为本机实际可执行文件）：

```bash
blender --background --factory-startup --python work/brick_factory.py -- --project-dir work/brick-project --width 1280 --height 720 --samples 32 --render
```

模板要求新的 project-dir，写入 `brick_factory.blend` 与 `frames/frame_0001.png` 至 `frame_0216.png`，拒绝覆盖现有项目。省略 render/still 只创建工程；`--still 74` 只生成指定帧，按用户要求或当前制作需要使用，不额外要求用户审批。项目帧率与动作时长固定，换成其他帧率/时长时须在复制后的源码里一起修改动作、相机和声音时间。

已创建工程继续渲染或恢复某段，用实际所需范围：

```bash
blender --background work/brick-project/brick_factory.blend --render-anim
blender --background work/brick-project/brick_factory.blend --frame-start 100 --frame-end 216 --render-anim
python3 work/mechanical_foley.py --output work/mechanical-foley.wav
```

将完整 PNG 序列以 24fps 编码为 9 秒 H.264 MP4，`yuv420p`、faststart；样本为无字幕的不透明画面。已有 ffmpeg-skill 时使用其 sequence.py 与 audio.py 完成序列合成和声音封装，参数按工具实际帮助；其他环境使用已验证的等价本地媒体工具。本仓库不捆绑 Blender/FFmpeg 或该 companion skill。

## 透明与剪映衔接

案例工程有地面、墙体和背景，默认输出 RGB；它是整帧场景，不是透明包装。用于口播时，在本次完整包装或指定范围内按 [自动导演规则](automatic-direction.md) 自主安排展示区间，覆盖原全屏人物，再在上方放同步圆窗或方窗，区间外由主包装承接；用户本次保留要求优先。

确需透明三维元素时：使用 `film_transparent`、RGBA 图像与保留 Alpha 的编码；同时检查几何地板/背景是否仍然覆盖整幅画面。PNG RGBA 转 QTRLE/ARGB MOV 是已有透明合成路径，不能只凭扩展名声称透明；本案例没有验证三维透明整片交付。所有层沿最终工程尺寸、帧率与 00:00 时间基准装配，口播原声只保留一份。
